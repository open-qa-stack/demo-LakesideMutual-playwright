## 1. quote-response-visible-to-customer

Respond to an open quote request and verify the response in Customer Self-Service (cross-application level, other, nominal, writes data). Application policy-management, domain insurance-quotes, functionality quote-response-customer-visibility.

- Intent: Verify that a Policy Management response to a submitted quote request becomes visible to the customer in their quote-request details.
- Sources: policy-management: /insurance-quote-requests/:requestid; customer-self-service: /policies/insurance-quote-requests/:id; policy-management-specs: policy-management-frontend.md
- Data: "8" (made-up); "admin@example.com" (customer-self-service); "1password" (customer-self-service)

### Step 1. Open the management details for the unanswered quote request

```ts
await page.goto("/insurance-quote-requests/8");
```

Expect 1.1: The request details show the open Health Insurance request for Max Mustermann.
- shows "Lakeside Mutual has not yet responded to this request." by its text

### Step 2. Open the response dialog and choose Reject so the customer can see the processed decision

```ts
await policyManagement.insuranceQuoteRequestsItem.respondButton.click();
```

Expect 2.1: The response dialog offers Accept and Reject choices.
- shows "Respond to Insurance Quote Request" in `page.getByText("Respond to Insurance Quote Request", { exact: true })`
- shows "Accept" in `page.getByRole("radio", { name: "Accept", exact: true })`
- shows "Reject" in `page.getByRole("radio", { name: "Reject", exact: true })`

### Step 3. Sign in to Customer Self-Service and open the same request details to check its current status

```ts
await customerSelfServicePage.goto(new URL("/login", process.env.OQAS_BASE_URL_CUSTOMER_SELF_SERVICE).href);
await customerSelfService.login.emailAddressTextbox.fill(process.env.CSS_DEMO_USERNAME!);
await customerSelfService.login.fillInButton.click();
await customerSelfService.login.logInButton.click();
await customerSelfServicePage.goto(new URL("/policies/insurance-quote-requests/8", process.env.OQAS_BASE_URL_CUSTOMER_SELF_SERVICE).href);
```

Expect 3.1: The customer can see the submitted request's current details.
- shows "You submitted the following Insurance Quote Request:" by its text
- shows "Lakeside Mutual has not yet responded to this Insurance Quote Request." in `page.getByText("Lakeside Mutual has not yet responded to this Insurance Quote Request.", { exact: true })`

## Not covered

The brief asks what follows, and no scenario does it:

- Test processing the request by making an offer and verifying the offered premium, policy limit, and expiration in the customer experience. The Policy Management response form shows two indistinguishable spinbuttons named “Amount in CHF”, so neither premium nor limit can be reliably targeted, and this environment’s UI exploration cannot submit a valid offer through the form.
- Test completing the full journey by submitting a new customer quote, processing that exact request, and checking its customer-visible result. Customer Self-Service displays many identically labelled quote rows, preventing selection of the newly submitted request unambiguously; the plan verifies the existing request response effect instead.
