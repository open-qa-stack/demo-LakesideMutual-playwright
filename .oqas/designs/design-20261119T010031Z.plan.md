## 1. policy-management-missing-request

Show an error for an unknown quote request (functional level, functional, negative, reads data). Application policy-management, domain insurance-quotes, functionality quote-request-history.

- Intent: Verify that requesting a non-existent quote identifier displays the not-found error instead of request details.
- Sources: policy-management; policy-management-specs: PMF-SCR-04 — Insurance quote request detail (`/insurance-quote-requests/:requestid`)
- Data: "999999" (made-up)

### Step 1. Open the details page for an unknown quote request

```ts
await page.goto("/insurance-quote-requests/999999");
```

Expect 1.1: The details page indicates an error and that the request was not found.
- shows "Error!" in `page.getByText("Error!", { exact: true })`
- shows "Insurance Quote Request not found." in `page.getByText("Insurance Quote Request not found.", { exact: true })`

## Not covered

The brief asks what follows, and no scenario does it:

- Soumettre une demande de devis dans l'espace client, la traiter dans Policy Management, puis vérifier l'effet visible pour le client. Les scénarios fonctionnels préexistants couvrent déjà l'envoi et l'apparition de la demande côté Policy Management, ainsi que l'ouverture du dialogue de réponse. L'élément non couvert est l'effet de la réponse sur l'écran client, mais les champs Insurance Premium et Policy Limit du dialogue Policy Management ont le même nom accessible et le navigateur ne peut pas cibler chaque champ de manière fiable; je n'ai donc pas soumis de réponse et ne peux pas vérifier son effet client sans risquer une modification mal ciblée.
