## 1. accepted-quote-visible-to-customer

Accept a quote and verify the customer can see the offer (cross-application level, other, nominal, writes data). Application policy-management, domain insurance-quotes, functionality quote-response.

- Intent: Submitting an accepted quote response in Policy Management must make the quote details available in Customer Self-Service for that customer.
- Sources: policy-management; customer-self-service; policy-management-specs: PMF-UC-10 — Respond to a quote request; customer-self-service-api: GET /insurance-quote-requests/{insuranceQuoteRequestId}
- Data: "18" (policy-management); "2026-12-18T23:59" (policy-management); "250" (policy-management); "100000" (policy-management)

### Step 1. Open the submitted Home Insurance quote request in Policy Management

```ts
await page.goto("/insurance-quote-requests/18");
```

Expect 1.1: The request detail shows a current quote request ready for response.
- shows "Home Insurance" in any of the 2 `page.getByText("Home Insurance", { exact: true })`
- shows "15. Nov 2026 20:00" in `page.getByText("15. Nov 2026 20:00", { exact: true })`

### Step 2. Open the response dialog and accept the request with the provided quote values

```ts
await policyManagement.insuranceQuoteRequestsItem.respondButton.click();
```

Expect 2.1: The response dialog defaults to acceptance and has a prefilled expiration date.
- shows "Respond to Insurance Quote Request" in `page.getByText("Respond to Insurance Quote Request", { exact: true })`
- shows "Accept" in `page.getByText("Accept", { exact: true })`
- shows "2026-12-18T23:59" as the value of `page.getByRole("textbox")`

### Step 3. Open Customer Self-Service to verify the quote outcome in the customer's account

```ts
await customerSelfServicePage.goto(new URL("/policies", process.env.OQAS_BASE_URL_CUSTOMER_SELF_SERVICE).href);
```

Expect 3.1: Customer Self-Service loads its customer policies screen after login.
- shows "Insurance Quote Requests" in `page.getByText("Show archived Insurance Quote Requests", { exact: true })`
- shows "Policies" in `page.getByRole("heading", { name: "Policies", exact: true })`
- shows "250 CHF" in `page.getByText("250 CHF", { exact: true })`
- shows "1000000 CHF" in `page.getByText("1000000 CHF", { exact: true })`

## 2. quote-rejection-visible-to-customer

Reject a quote and verify the customer sees the request status (cross-application level, other, nominal, writes data). Application policy-management, domain insurance-quotes, functionality quote-response.

- Intent: Rejecting an open quote request in Policy Management must update its status so that Customer Self-Service no longer presents it as awaiting a quote.
- Sources: policy-management; customer-self-service; policy-management-specs: PMF-UC-10 — Respond to a quote request; customer-self-service-api: GET /insurance-quote-requests/{insuranceQuoteRequestId}
- Data: "18" (policy-management)

### Step 1. Open the submitted Home Insurance quote request in Policy Management

```ts
await page.goto("/insurance-quote-requests/18");
```

Expect 1.1: The request detail is ready for a staff response.
- shows "Home Insurance" in any of the 2 `page.getByText("Home Insurance", { exact: true })`
- shows "15. Nov 2026 20:00" in `page.getByText("15. Nov 2026 20:00", { exact: true })`

### Step 2. Open the response dialog and select Reject

```ts
await policyManagement.insuranceQuoteRequestsItem.respondButton.click();
await policyManagement.insuranceQuoteRequestsItem.rejectRadio.click();
```

Expect 2.1: The dialog reflects rejection and removes the accept-only fields.
- shows "Reject" in `page.getByText("Reject", { exact: true })`
- shows "Send Response" in `page.getByRole("button", { name: "Send Response", exact: true })`
- no longer shows "Expiration Date" in `page.getByText("Expiration Date", { exact: true })`
- no longer shows "Insurance Premium" in `page.getByText("Insurance Premium", { exact: true })`
- no longer shows "Policy Limit" in `page.getByText("Policy Limit", { exact: true })`

### Step 3. Open Customer Self-Service to check the updated request status

```ts
await customerSelfServicePage.goto(new URL("/policies", process.env.OQAS_BASE_URL_CUSTOMER_SELF_SERVICE).href);
```

Expect 3.1: The customer account displays its insurance quote request list and policy section.
- shows "Insurance Quote Requests" in `page.getByText("Show archived Insurance Quote Requests", { exact: true })`
- shows "Policies" in `page.getByRole("heading", { name: "Policies", exact: true })`

## Not covered

The brief asks what follows, and no scenario does it:

- Créer et modifier un contrat dans Policy Management, puis vérifier son effet dans une autre application. Le compte de démonstration Customer Self-Service n’a pas de liaison vérifiable avec un contrat créé ou modifié dans Policy Management à partir des écrans explorés ; aucun effet interapplication fiable ne peut donc être asserté ici.
- Traiter les demandes de devis et vérifier que le client voit le résultat dans une autre application. Les scénarios proposés couvrent déjà le traitement par acceptation et rejet avec la vérification côté Customer Self-Service.
- Consulter un contrat Policy Management et vérifier le même contrat dans une autre application. Les écrans explorés montrent des polices du compte démo Customer Self-Service sans permettre d’établir qu’elles sont le contrat Policy Management de graine.
