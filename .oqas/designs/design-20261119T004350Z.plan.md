## 3. quote-request-overview

Review quote requests and policies on the overview (functional level, other, nominal, writes data). Application customer-self-service, domain insurance-quotes, functionality customer-quote-request-overview.

- Intent: Verify the customer policies overview presents the quote-request list and contract information needed in the requested self-service consultation; sign-in establishes a session without altering the underlying quote requests.
- Sources: customer-self-service: /policies
- Data: none

### Step 1. Open the login screen

```ts
await page.goto("/login");
```

### Step 2. Sign in with the displayed demo credentials

```ts
await customerSelfService.login.fillInButton.click();
await customerSelfService.login.logInButton.click();
```

### Step 3. Review the quote-request list on the policies overview

```ts
await customerSelfService.login.logInButton.click();
```

Expect 3.1: The overview displays quote-request entries for Home Insurance, with a visible request status.
- shows "Insurance Quote Requests" in `page.getByText("Show archived Insurance Quote Requests", { exact: true })`
- shows "Home Insurance" in any of the 19 `page.getByRole("cell", { name: "Home Insurance", exact: true })`

## Not covered

The brief asks what follows, and no scenario does it:

- Verify entering a distinct billing address beside the contact address in the quote wizard. After unchecking Same as Contact Address, the repeated address textboxes have duplicate accessible names and no unique labels or test IDs; the browser tool reported they cannot be targeted uniquely.
- Verify submitting a completed quote request and seeing it in the list. Submission creates persistent shared environment data, and no reliable cleanup or reset path was established during exploration, so a repeatable write test could not be planned safely.
