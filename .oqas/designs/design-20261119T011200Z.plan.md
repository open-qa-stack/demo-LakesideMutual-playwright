## Not covered

The brief asks what follows, and no scenario does it:

- Compare the dialog's wrong-input validation state and resulting messages. The premium and policy-limit fields both have the same accessible name, "Amount in CHF", with no distinguishing locator or container exposed; browser tools cannot reliably target an individual input to reach that state.
- Exercise the complete cross-application journey by submitting a new quote request in Customer Self-Service, processing it in Policy Management, and comparing its resulting state back in Customer Self-Service. This plan is restricted to functional-level visual comparisons, which can cover one screen state at a time but not the required multi-application business journey; submission also writes shared data and would need explicit repeat-safe handling.
