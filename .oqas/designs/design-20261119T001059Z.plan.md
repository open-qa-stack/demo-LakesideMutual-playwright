## 4. reject-submitted-quote

Reject a submitted quote request (business level, other, nominal, reads data). Application policy-management, domain insurance-quotes, functionality quote-request-response.

- Intent: Verify staff can review a submitted request and choose the rejection path; the response form is cancelled so the source request remains submitted for repeat-safe testing.
- Sources: policy-management; policy-management-specs: policy-management-frontend.md § PMF-UC-08 — Review insurance quote requests; policy-management-specs: policy-management-frontend.md § PMF-UC-09 — Follow the history of a quote request; policy-management-specs: policy-management-frontend.md § PMF-UC-10 — Respond to a quote request
- Data: "18. Nov 2026 21:03" (policy-management); "Home Insurance" (policy-management); "Max Mustermann" (policy-management); "1000 CHF" (policy-management); "Reject" (policy-management)

### Step 1. Open the quote-request list

```ts
await page.goto("/insurance-quote-requests");
```

Expect 1.1: The open requests table identifies a pending request.
- shows "Insurance Quote Requests" in `page.getByRole("heading", { name: "Insurance Quote Requests", exact: true })`
- shows "Open Insurance Quote Requests" by its text
- shows "18. Nov 2026 21:03" in `page.getByRole("cell", { name: "18. Nov 2026 21:03", exact: true })`
- shows "Home Insurance" in any of the 26 `page.getByRole("cell", { name: "Home Insurance", exact: true })`
- shows "Request open" in any of the 21 `page.getByRole("cell", { name: "Request open", exact: true })`

### Step 2. Open the request details

```ts
await policyManagement.insuranceQuoteRequests.showDetailsButtonInRow("18. Nov 2026 21:03").click();
```

Expect 2.1: The request details show its customer, insurance type, deductible and pending status.
- shows "Home Insurance" in any of the 2 `page.getByText("Home Insurance", { exact: true })`
- shows "Max Mustermann" in any of the 2 `page.getByRole("link", { name: "Max Mustermann", exact: true })`
- shows "1000 CHF" in `page.getByText("1000 CHF", { exact: true })`
- shows "Lakeside Mutual has not yet responded to this request." by its text

### Step 3. Open the response dialog and select Reject

```ts
await policyManagement.insuranceQuoteRequestsItem.respondButton.click();
await policyManagement.insuranceQuoteRequestsItem.rejectRadio.check();
```

Expect 3.1: Reject is selected and the acceptance-specific amount/date controls disappear.
- shows "Reject" in `page.getByRole("radio", { name: "Reject", exact: true })`
- no longer shows "Expiration Date" in `page.getByText("Expiration Date", { exact: true })`
- no longer shows "Insurance Premium" in `page.getByText("Insurance Premium", { exact: true })`
- no longer shows "Policy Limit" in `page.getByText("Policy Limit", { exact: true })`

### Step 4. Cancel to leave the request unchanged

```ts
await policyManagement.insuranceQuoteRequestsItem.cancelButton.click();
```

Expect 4.1: The dialog closes and the request remains unanswered.
- shows "Lakeside Mutual has not yet responded to this request." by its text
- shows "Respond" in `page.getByRole("button", { name: "Respond", exact: true })`
- no longer shows "Respond to Insurance Quote Request" in `page.getByText("Respond to Insurance Quote Request", { exact: true })`

## Not covered

The brief asks what follows, and no scenario does it:

- Create a policy, modify a policy and treat quote requests including acceptance offers. La création et la modification ne peuvent être réalisées sûrement car les champs ne sont pas identifiables; le traitement des demandes est exercé dans le plan comme consultation du formulaire et annulation, sans altérer les demandes partagées. La réponse par offre nécessite les champs dupliqués non accessibles.
